## Решения
<!-- дата · этап · решение · почему · как поменять конфигом -->
- 06.10.2026 · M0 · Alembic живёт в `services/api` (`alembic.ini`, `migrations/`), `env.py` асинхронный (asyncpg), URL только из `DATABASE_URL`; ревизия `0001` делает лишь `CREATE EXTENSION IF NOT EXISTS timescaledb`, downgrade расширение не удаляет · схемой владеет API (FR-DB-01 sync справочников при старте api); `DROP EXTENSION` уничтожил бы гипертаблицы · `make migrate` (с хоста, `HOST_DATABASE_URL`), в контейнере `alembic -c services/api/alembic.ini upgrade head`.
- 06.10.2026 · M0 · Тесты — один корневой `tests/` по областям: `tests/twin_core`, `tests/services`, `tests/integration` (дальше `tests/sim`, `tests/e2e`, `tests/load` по SPEC §4.4); интеграционные помечены `@pytest.mark.integration` и не входят в `make check`, `make test` сам поднимает инфраструктуру; общие хелперы — `tests/support.py` · один прогон pytest на весь workspace; SPEC уже ссылается на `tests/sim/test_calibration.py` · маркеры и пути — `[tool.pytest.ini_options]` в `pyproject.toml`.
- 06.10.2026 · M0 · Формат Redis-ключа `plant:clock` — строка JSON v1: `{"v":1,"plant_time":"…Z","wall_ts":"…Z","speed":60.0,"paused":false,"sim_mode":"live"}`; читатели экстраполируют `plant_time + (wall_now − wall_ts) × speed` (на паузе — без экстраполяции); `sim` переписывает ключ при старте/паузе/смене скорости/сбросе и ~раз в секунду; `SimClock.is_stale` — нет обновлений > 10 с · `Clock.now()` синхронный и дешёвый, без запроса в Redis на каждый вызов; запись и чтение — `publish_clock_state` / `SimClock` в `twin_core.clock` · `CLOCK_MODE=sim|system`; формат описан в docstring `twin_core/clock.py`.
- 06.10.2026 · M0 · Значение `CLOCK_MODE` по умолчанию в коде — `system` (в `.env.example` и compose — `sim`) · библиотека и тесты на хосте не должны требовать Redis · переменная `CLOCK_MODE`.
- 06.10.2026 · M0 · Модели конфига строгие (`extra="forbid"`, неизвестный ключ — ошибка с подсказкой имени поля), дубли ключей YAML — ошибка; загрузчик собирает все проблемы сразу: файл, строка, путь с кодами (`areas[WELD].lines[WELD-1].ict_seconds`), значение, ближайший код (Левенштейн или единственное совпадение по подстроке); сервис с битым конфигом не стартует (код 2, список ошибок в stderr) · опечатка не должна молча превращаться в значение по умолчанию (AC M0, FR-DOM-01) · `python -m twin_core.config [DIR]` / `make config-check` для проверки.
- 06.10.2026 · M0 · Коды активов уникальны сквозь все виды (площадка/участок/линия/оборудование/буфер); имена для FR-DOM-02 = код + `aliases` + `name_ru`/`name_kk` (у продукта `name`), уникальны внутри вида; сравнение без учёта регистра, пробелов, вида тире и «ё» · события несут только код сущности; импорт ищет по русским названиям · `aliases` в YAML.
- 06.10.2026 · M0 · Семантические проверки сверх ссылок: буфер идёт вниз по потоку; причины отказов/микроостановок/сценариев — `planned=false`, плановое ТО — `planned=true`; типы дефектов участка — своего участка или `ANY`; сигналы `telemetry` и `set_state` — из сигналов типа (`set_state` ещё `degradation`, если у типа есть износ); медиана микроостановки < `microstop_threshold_s`; начальный уровень буфера ≤ ёмкости; доля причин/микса = 1; доп. рабочий день — не праздник и не обычный рабочий день; причина `UNK` обязательна (FR-ENG-02) · ошибки ловятся до запуска симулятора · правки YAML.
- 06.10.2026 · M0 · Tag map: `PLANT_TAG_MAP`, иначе первый существующий из `tag_map.yaml` (пилот) → `tag_map.demo.yaml` (демо), иначе без карты; `tag_map.example.yaml` проверяется тестом; сигнал `degradation` в карте запрещён схемой (FR-SIM-02) · один образ collector для demo/prod без переменных по профилю · `PLANT_TAG_MAP=<файл>`.
- 06.10.2026 · M0 · NFR-11: AST-тест `tests/test_nfr11_no_wall_clock.py` (с учётом алиасов импорта) + ruff `TID251` banned-api на `datetime.now/utcnow/today`, `date.today`, `time.time/time_ns`; разрешено только `twin_core/clock.py` · линтер ловит в редакторе, тест — в CI · allowlist в тесте и `per-file-ignores`.
- 06.10.2026 · M0 · Заглушки сервисов — общий `twin_core.health.run_stub`: проверка конфига + `/healthz`, `/readyz`; порты: sim 8100 (будущий пульт), collector 8110, engine 8120, notifier 8130 (только внутри сети compose), api 8000 (FastAPI), web 3000; один `infra/python.Dockerfile` с `ARG PACKAGE` (без BuildKit-синтаксиса: в colima нет buildx) · `depends_on: service_healthy` работает с первого дня · `HEALTH_PORT`.
- 06.10.2026 · M0 · `make up` без профиля — только инфраструктура (timescaledb, redis, mqtt без профиля); `make up PROFILE=demo|prod` — плюс сервисы; collector зависит от sim с `required: false`; TimescaleDB ограничен `TS_TUNE_MEMORY=1GB`, Redis `maxmemory 512mb` · укладываемся в colima 6 ГБ · `PROFILE`, значения в `docker-compose.yml`.

- 06.10.2026 · M0 · Зависимости вне SPEC §4.3 (правило 9): `httpx2` (dev; TestClient Starlette 1.x требует его вместо `httpx`); стек shadcn/ui — `lucide-react`, `class-variance-authority`, `clsx`, `tailwind-merge`, `@radix-ui/react-slot`; `@fontsource-variable/inter` (локальный шрифт, FR-UI-02); `@eslint/eslintrc` (flat config для `eslint-config-next` 15); pnpm 12 `allowBuilds: false` для `@parcel/watcher`, `@swc/core` (next-intl) и `unrs-resolver` (eslint) — у всех готовые бинарники · минимальный набор для каркаса · `web/package.json`, `web/pnpm-workspace.yaml`.
