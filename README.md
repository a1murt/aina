# Aina — цифровой двойник автомобильного завода

Aina показывает цех в реальном времени, считает KPI по ISO 22400, находит узкое место, оценивает риск отказа оборудования на 8 часов вперёд и прогнозирует выполнение плана месяца с what-if. Данные приходят от виртуального завода по OPC UA и MQTT — так же, как от контроллеров. Для пилота достаточно заполнить карту тегов и указать адрес OPC UA-сервера завода.

## Что умеет

| Задача | Как решена |
|---|---|
| Визуализация участков и оборудования | живая SVG-схема цеха: 4 участка одной линии (сварка → окраска → сборка → ОТК), 14 единиц оборудования, буферы, движение кузовов, режим ТВ |
| Мониторинг KPI | OEE = доступность × эффективность × качество (ISO 22400), выпуск против плана, простои, брак по участкам |
| Инциденты и отклонения | оповещения с оценкой потерь в машинах, эскалация, Telegram; терминал оператора: андон и причина остановки в 3 касания |
| Панель руководителя | выпуск с начала месяца, прогноз P10–P90, вероятность плана 4 800 и цели 5 500, топ потерь и рычагов в машинах и ₸ |
| Прогноз простоев и узких мест (ИИ) | LightGBM + SHAP: риск отказа робота/конвейера на 8 ч вперёд с объяснением; время до предела по сигналам; узкое место методом активных периодов; Монте-Карло плана месяца с what-if; SPC и корреляции брака; сменный рапорт, где каждая цифра сверяется с данными (текст — шаблон или локальная языковая модель) |

**Линия** здесь — весь поток сварка → окраска → сборка → ОТК. В модели это 4 участка (`WELD-1`, `PAINT-1`, `ASSY-1`, `QC-1`) и 14 единиц оборудования. Эффект и пилот считаются на линию целиком.

**Аудит заводских данных за секунды.** Загрузка выгрузки завода за 01–02.10.2026 (`case2_data.docx`, или xlsx/csv) сразу показывает: брак окраски 5,17% при норме 2%, Конвейер-03 — 55 из 60 допустимых минут простоя, 5 расхождений журнала простоев с потерянным временем, проедание буфера перед сборкой, план 4 800 против цели 5 500. Цель 5 500 недостижима без дополнительных смен: потолок линии ≈ 5 191 машин за 42 смены.

## Запуск

Нужны Docker с Compose, `make`, `uv`, Node 20+ и `pnpm`.

```bash
make demo
```

Веб — http://localhost:3000, API — http://localhost:8000/api/docs. Пользователи по ролям: `director`, `master`, `operator`, `maintenance`, `quality`, `admin`, пароль `qost2026`. Сброс к началу демо — `make demo-reset`, сценарии S1–S5 — на экране `/demo`. Всё работает без интернета.

Исходные выгрузки завода (01–02.10.2026) в репозиторий не выложены. Если положить их в `data/case/source/`, `make demo` импортирует docx; иначе — XLSX-копию тех же данных из `data/case/csv/` с тем же результатом.

## Стек и стандарты

Python 3.12 (FastAPI, SimPy, asyncua, LightGBM, SHAP, NumPy), TimescaleDB, Redis, Mosquitto, Next.js 15 + ECharts, Docker Compose. ISO 23247 (цифровой двойник), ISA-95 (модель активов), ISO 22400 (KPI), OPC UA и MQTT UNS, IEC 62443 (двойник в DMZ, только чтение из OT), ISA-101 (HMI).

| Каталог | Что |
|---|---|
| `services/sim` | виртуальный завод: модель потока, отказы и износ, брак, телеметрия, OPC UA-сервер, MQTT, пульт сценариев |
| `services/collector` | сбор по OPC UA/MQTT только на чтение, буфер на диске при обрыве связи |
| `services/engine` | состояния, простои, KPI, узкое место, сверка данных, оповещения, прогноз отказов |
| `services/api` | REST + WebSocket, роли, импорт, прогноз, LLM-рапорты, копилот |
| `services/notifier` | Telegram-бот оповещений |
| `packages/twin_core` | общее ядро: конфиг завода, KPI, календарь, правила, прогноз |
| `ml/` | датасет, обучение и модели предиктивного ТО |
| `web/` | веб-интерфейс по ролям |
| `config/` | модель завода, пороги, причины, дефекты, параметры симуляции, бизнес-допущения |
| `docs/` | архитектура, сценарий демо, план пилота, ТЗ, журнал решений |
